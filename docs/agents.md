# Agents -- stage router and experience filter

`agents/router.py:route_stage` is a deterministic, top-to-bottom rule chain (contain > preserve > remediate > harden > restore) -- no model call, matching the design doc's "LLMs routing LLMs is where live demos die." `stage_tools` applies the experience filter: a tool this environment's postmortem history shows as 100% failures for a given entity is removed from that turn's list via `memory/store.py:precedent_stats`, reusing the same signal Gate 4 uses rather than a separate "decisions" table. Depends on `control/registry.py`. Breaks if `precedent_stats`'s failure-rate threshold (currently exactly 1.0, i.e. every recorded precedent failed) is loosened without checking whether that starts filtering a tool with only one bad data point out of many good ones.

`agents/plan_builder.py:build_plan` is the design doc's own sanctioned substitute for a live agent when time or Bedrock access is short (`references/iterations.md` cut order, item 6: "cached responses and the scripted ... client") -- here it's not a fallback, it's the only option, since this environment has no Bedrock access at all. It refuses to build a plan on an abstained `CausalVerdict`, or for a tool the stage/experience filter doesn't currently offer, and otherwise assembles a schema-valid `ActionPlan` with `justification_ref` wired to the verdict. `agents/test_plan_builder.py` proves the full loop with no AWS: a synthetic incident through `causal/falsify.py` -> `route_stage` -> `build_plan` -> schema validation -> a real Gate 2 pass.

What this does *not* do, and cannot without Bedrock: reason about concrete numeric args (which revision to roll back to, a safe `desired_count`) from live telemetry -- that stays the caller's job, passed in as `args`. The 2-retry counterexample loop and response caching for a live agent are likewise not implemented, since there is no live agent to retry or cache.
